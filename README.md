## 제작 목적

코딩을 처음 하는 학부생 대상 특강입니다. 150분 안에 **아이디어부터 배포까지 한 사이클**을 손으로 끝내는 게 목표라, 강의 자료가 다음 세 가지를 동시에 해내야 했습니다.

**1. 발제와 실습이 끊기지 않을 것**
강의실 프로젝터로 슬라이드를 띄우는 동안, 수강생은 자기 노트북에서 같은 내용을 따라갑니다. 슬라이드에 프롬프트를 띄워놓고 받아 적게 하면 오타로 시간을 다 씁니다. 그래서 발제용 슬라이드와 **복사해서 쓰는 프롬프트 페이지**를 분리했습니다.

**2. 놓쳐도 혼자 따라올 수 있을 것**
한 단계라도 막히면 그 뒤가 전부 밀립니다. 프롬프트 페이지는 파트별로 접어두고, 각 단계마다 **실제 실행 화면 사진**을 붙여서 어디까지 왔는지 스스로 대조할 수 있게 했습니다.

**3. 결과물이 남을 것**
"만들었다"로 끝나지 않고 **인터넷에 열려 있는 내 주소**가 나와야 합니다. 쉬는시간에 서로 구경하는 공유 페이지를 두어, 배포가 강의의 하이라이트가 되도록 배치했습니다.

여기에 더해, 뭘 만들지 못 정한 사람을 위한 브레인스토밍 페이지와 불참자용 대체 과제 안내를 붙였습니다.

### `/slide` — 발제 슬라이드

<!-- 스크린샷: 슬라이드 -->

강의실 프로젝터에 띄우는 53장. 화살표로 넘기고, <kbd>O</kbd> 를 누르면 전체 목차가 뜹니다.
개념 설명, 따라 할 순서, 그때그때 입력할 프롬프트가 파트 순서대로 들어 있습니다.

### `/prompt` — 프롬프트 모음

<!-- 스크린샷: 프롬프트 -->

수업 중 받아 적지 않고 복사해서 쓰는 페이지입니다. 파트별로 접혀 있고, 펼치면 그 단계에서 입력할 내용이 나옵니다.

- 블록마다 **복사 버튼**. 눌러서 그대로 붙여넣으면 됩니다
- **터미널**(검은 화면에 치는 것) / **프롬프트**(AI에게 하는 말) / **명령**(`/` 로 시작) 을 색으로 구분
- 단계마다 **실제 실행 화면 사진**. 내 화면이 맞게 가고 있는지 대조할 수 있습니다

### `/share` — 결과물 공유

<!-- 스크린샷: 공유 -->

이름, 배포한 주소, 한 줄 설명을 올리면 카드로 쌓입니다. 카드를 누르면 그 사이트가 새 탭으로 열립니다.
주소는 `example.com` 처럼 대충 적어도 알아서 맞춰지고, 같은 주소는 한 번만 올라갑니다.

### `/idea` — 브레인스토밍

<!-- 스크린샷: 아이디어 -->

뭘 만들지 못 정한 사람이 질문에 하나씩 답하면, 그대로 AI에 붙여넣을 프롬프트가 만들어집니다.

```
[어디에 쓸 건지] → [어디서 출발할지] → [질문에 답하기] → [프롬프트 완성]
```

- **어디에 쓸 건지** — 해커톤 / 사이드 프로젝트 / 아이템 탐색. 고른 것에 따라 뒤 질문이 달라집니다
- **어디서 출발할지** — 내가 직접 겪는 불편 / 옆에서 본 남의 불편
- 답을 너무 짧게 쓰면 다음으로 넘어가지 않습니다. 두루뭉술하게 적으면 프롬프트도 쓸모없어지니까요
- 옆에서 본 불편인데 **그 사람에게 물어볼 수 없다**고 하면 거기서 막습니다. 만날 수 없는 사람의 문제는 결국 상상으로 만들게 됩니다

### `/assignment` — 대체 과제

특강에 참여하지 못한 사람을 위한 안내입니다. 강의 내용대로 만들고, 배포하고, `/share` 에 올리면 제출이 끝납니다.
배포한 주소가 **다른 사람에게도 열리는지** 확인하는 방법을 따로 짚어두었습니다. 여기서 가장 많이 막힙니다.

## 기술 구성

빌드 도구가 없습니다. HTML을 열면 그게 그대로 배포본입니다.

| | |
| --- | --- |
| 호스팅 | Vercel 정적 배포 |
| 폰트 | Pretendard (CDN) |
| DB | Supabase — `/share` 의 등록·목록에만 사용 |
| 빌드 | 없음. 프레임워크·번들러·패키지 매니저 모두 없음 |

**왜 빌드 도구를 안 썼나**
수강생 절반이 휴대폰으로 보고, 강의 도중에도 문구를 고쳐야 합니다. 빌드 단계가 있으면 그때마다 파이프라인이 걸립니다. 페이지당 HTML 한 장을 유지하면 고치고 바로 올릴 수 있습니다.

**디자인 규칙**
흰 배경(`#FFFFFF`)과 크림슨(`#801A2C`) 두 축, 폰트는 Pretendard 하나. 색과 폰트를 묶어두면 페이지를 새로 만들어도 같은 얼굴이 나옵니다.

<details>
<summary><b>폰트를 하나로 줄인 이유</b></summary>

원래는 Wanted Sans(본문) + JetBrains Mono(코드) 두 벌이었습니다. 두 가지 문제가 있었습니다.

- **Wanted Sans** — CDN 경로가 404라 처음부터 로드된 적이 없었습니다. 본문이 계속 브라우저 기본 폰트로 렌더링되고 있었습니다
- **JetBrains Mono** — 한글 글리프가 없습니다. 커리큘럼 표의 「쉬는시간」·「자율 실습」이 시스템 한글 폰트로 떨어지면서 그 줄만 튀어 보였습니다

지금은 Pretendard 하나로 통일하고, 코드·라벨은 자간 0과 `tabular-nums` 로만 본문과 구분합니다.

</details>

## 파일 구조

```
index.html              메인
slide/index.html        발제 슬라이드
prompt/index.html       프롬프트 모음
share/index.html        결과물 공유
idea/index.html         브레인스토밍
assignment/index.html   대체 과제 안내
styles.css              공통 디자인 토큰
img/                    실행 예시 사진 30장
```

`styles.css` 의 `:root` 토큰과 리셋은 모든 페이지가 함께 씁니다. `.page` 로 시작하는 규칙은 읽는 페이지 전용이고, `/slide` 는 `body` 에 `.page` 가 없어 영향을 받지 않습니다. 슬라이드 전용 스타일은 `slide/index.html` 안에 그대로 둡니다.

## 로컬에서 보기

빌드가 없으니 정적 서버 하나면 됩니다.

```bash
python -m http.server 4321
```

`/share` 는 Supabase anon key를 `share/index.html` 안에 직접 두고 있습니다. 빌드 도구가 없어 환경변수를 주입할 방법이 없기 때문이고, **anon key는 원래 클라이언트에 노출되는 공개 키**입니다. 테이블은 RLS로 `select` / `insert` 만 열려 있어 `update` / `delete` 는 막혀 있습니다.
